Exact cell decomposition for coverage

Sampling planners burn memory on samples and start missing narrow gaps as obstacle density rises. Exact decomposition does not: it plans through every gap regardless of width, which is the guarantee I wanted.

  • Motion Planning

My part Solo.

Problem

Plan a route through a workspace of known circular obstacles. A probabilistic roadmap would have been the obvious answer, but its performance depends on sampling density and it can miss a narrow passage entirely. I had already built an RRT for a 2-DoF arm, so I knew what I would be giving up.

Approach

A sweep line over the critical x-coordinates of every circle, splitting the free space into trapezoidal cells bounded by obstacle arcs, and an adjacency graph built as cells open and close. Travelling between two points becomes: find the cell containing each, then walk the graph through the midpoints of shared edges.

Outcome

It plans through every gap in the workspace. Two honest caveats: the graph search over the cell adjacency is a breadth-first cost relaxation rather than the A* the README claims, so the route is not guaranteed shortest; and despite the repository name I did not implement the complete-coverage traversal, which my own notes admit.
