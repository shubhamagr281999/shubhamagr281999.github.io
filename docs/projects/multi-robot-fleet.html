Jul 2021 – Jan 2022 · Flipkart GRiD 3.0

A warehouse fleet that was not allowed to know where it was

Flipkart's brief said the robots could not localise themselves: one ceiling camera had to place the whole fleet. That single constraint forced everything, and it was also the thing that never fully worked.

  • Motion Planning
  • Perception

My part Repo owner and majority contributor across six months. I built the robot model and Gazebo arena, the overhead-camera localisation, the fleet manager, and the planner modifications. Teammates built the microcontroller firmware, the reactive avoidance layer and the chute queueing.

Repository

Problem

Build a small-scale version of a sortation fleet and improve its throughput. Each robot had to fit in a six-inch square, carry a cube on a tray that flips to drop it, and take all of its position knowledge from an overhead camera. So: centralised multi-agent planning over robots that cannot sense themselves, with real lens distortion and real timing jitter in between.

Approach

I built the parametric robot model and the Gazebo arena with an overhead camera, and the marker-based estimator that turns detections into fleet poses in grid coordinates. For planning I took an open-source conflict-based search implementation and made it plan for real differential-drive robots: I added heading to the search state so that turning costs time, and widened the conflict test by a timestep so two robots arriving one tick apart in the same cell count as a conflict. On the mechanical side I designed the chassis and the later three-wheel omni-drive revision, and wrote the inverse transform from body velocities to wheel speeds.

Outcome

We reached round two, a physical arena was built and a bot drove on it. The full multi-agent stack worked in simulation. The localisation never fully stabilised: the last commit in the repository is a teammate still fixing the estimator, and the code ends configured for a single robot after scaling down to debug hardware. There is no throughput measurement, which is awkward given throughput was the brief.
